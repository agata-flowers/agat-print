# Stage 17.4 — Complete Marketplace UX/UI Prototype

## Цель

Создать автономный интерактивный frontend-прототип многопродавцового
маркетплейса AGAT PRINT, который позволяет проверить полный UX товаров и
полиграфических услуг до подключения существующего backend. Stage 17.4 не
меняет API, базу данных, production-конфигурацию или доменные инварианты
Stages 1–15.

Визуальный ориентир — пропорции, плотность, сетка и предсказуемость ведущих
маркетплейсов Узбекистана. Чужие логотипы, тексты, изображения и уникальные
брендовые элементы не используются.

## Последовательные подэтапы

### 17.4.1 — Design system и application shell

- централизованные токены типографики, пространства, радиусов и цвета;
- контейнер 1240–1360 px, 5–6 карточек на широком desktop;
- двухуровневая responsive-навигация, каталог, mobile bottom navigation;
- browser history, активный маршрут и восстановление прокрутки;
- конфигурируемое имя/логотип бренда.

**Приёмка:** 1920/1440/1366/1280/1024/768/430/375 px без горизонтального
скролла, touch targets не менее 40 px, `prefers-reduced-motion`.

### 17.4.2 — Каталог, поиск и рекомендации

- отдельные деревья категорий товаров и услуг;
- поиск, категория, продавец, наличие, диапазон цен, сортировка;
- главная с баннерами, услугами, новинками, скидками и тематическими полками;
- уникальная порционная infinite feed;
- локальная объяснимая рекомендация на просмотрах, категориях и избранном.

**Приёмка:** поиск находит товары и услуги; комбинации фильтров воспроизводимы;
повторяющиеся SKU не добавляются; модель помечена как демонстрационная.

### 17.4.3 — Multi-vendor товары, магазины и checkout

- frontend-модель Seller, Product, Offer, Variant, Stock и Review;
- несколько предложений продавцов для одного товара;
- страницы товара и магазина;
- корзина, сгруппированная по продавцу, адрес/получение и demo-checkout;
- сохранение корзины, избранного, истории и позиции прокрутки локально.

**Приёмка:** цена/остаток выбранного предложения соблюдаются; недоступный товар
нельзя заказать; checkout создаёт только локальный демонстрационный заказ.

### 17.4.4 — Полиграфические услуги

- отдельные маршруты и специализированные мастера для шести услуг;
- файлы, формат, бумага, размер, количество, обработка и дополнительные опции;
- для сложных услуг — техническое задание, материалы и срок;
- валидация, предварительная цена, исполнитель/точка и отдельное подтверждение.

**Приёмка:** услуга никогда не попадает в товарную корзину; обязательные поля
валидируются; реальные файлы не загружаются и production-заказы не создаются.

### 17.4.5 — Кабинеты покупателя и продавца

- профиль, адреса, заказы, timeline, избранное, уведомления, отзывы, настройки и
  поддержка покупателя;
- ассортимент, редактирование товара, изображения, цены, остатки, заказы,
  статистика и настройки магазина продавца;
- локальные изменения продавца отражаются в каталоге.

**Приёмка:** все элементы управления имеют видимое действие; localStorage
переживает reload; reset demo-data явно восстанавливает исходный seed.

### 17.4.6 — Verification и автономный Windows artifact

- unit-тесты модели/фильтров/рекомендаций/checkout;
- Playwright всех маршрутов, товаров, услуг, buyer/seller кабинетов, history и
  responsive viewports с `retries: 0`;
- production build, полный workspace CI и последовательная regression-цепочка;
- автономный Windows ZIP без Docker/Node.js с fallback портов 4173–4183;
- desktop/mobile screenshots и машинно-проверяемый verification report.

## Маршруты прототипа

| Маршрут | Назначение |
| --- | --- |
| `/premium` | рекомендательная главная |
| `/premium/catalog` | товары и услуги, поиск/фильтры/сортировка |
| `/premium/category/:slug` | категория товаров |
| `/premium/product/:id` | товар и предложения продавцов |
| `/premium/store/:slug` | публичная страница магазина |
| `/premium/service/:id` | специализированный мастер услуги |
| `/premium/cart` | корзина по продавцам |
| `/premium/checkout` | демонстрационный checkout товаров |
| `/premium/account/:section` | кабинет покупателя |
| `/premium/seller/:section` | кабинет продавца |

Маршруты реализуются через History API без сетевого роутера, чтобы автономный
Windows server мог отдавать один безопасный SPA entry point.

## Общие критерии приёмки

1. Все видимые кнопки, ссылки, фильтры и формы имеют осмысленную реакцию.
2. RU/UZ/EN покрывают весь новый пользовательский текст; доменное состояние не
   зависит от языка.
3. Товары и услуги имеют отдельные модели и checkout.
4. Multi-vendor предложения, остатки и группировка корзины проверены.
5. Back/Forward и scroll restoration работают без потери состояния.
6. Прототип не отправляет production mutation/API requests и явно маркирован
   как demo.
7. Нет реальных платежей, доставки, документов или персональных данных.
8. Backend, API, Prisma и production не изменены.
9. Полный CI и Stage 17.4 artifact успешны на одном SHA.

Stage 18 и backend integration не входят в Stage 17.4.
